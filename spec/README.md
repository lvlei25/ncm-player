# spec/ 规格目录

本目录是项目的**唯一事实来源**：改动先落规格，再落代码。

| 文件 | 作用 |
| --- | --- |
| `requirements.md` | 需求与可量化验收标准（含实测基线、验收结果） |
| `design.md` | 技术方案、取舍与风险 |
| `tasks.md` | 任务清单与逐项完成情况 |
| `changelog.md` | **所有变更记录**（新增/修改/删除都要记） |
| `testing.md` | 测试策略、分层、门禁、缺陷分级 |

## 变更记录规则

任何一次改动都必须遵守：

1. **先改 `requirements.md`**：新增/调整需求，写清验收标准与量化指标。
2. **再改 `tasks.md`**：拆成可勾选任务，完成后标注实测数据。
3. **实现后追加 `changelog.md`**：写清「改了什么 / 为什么 / 影响哪些文件 / 如何验证」。
4. **规格与代码同一提交**：不允许代码先合入、规格事后补。
5. **删除也要记**：删文件、删导出、删依赖同样写入 changelog，并说明理由。
